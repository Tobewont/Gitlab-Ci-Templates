# 构建、缓存与镜像约定

> 本文档由仓库根 `README.md` 拆分而来，聚焦「构建、缓存与镜像约定」。总览与导航见 [README](../README.md)。

## Docker Build 姿势

| 能力 | 姿势 | 说明 |
|---|---|---|
| `.docker-build` | 走宿主 `docker.sock`（默认） | k8s runner 已挂载 `/var/run/docker.sock`；无 dind service，速度最好 |
| `.docker-build-dind` | dind service | k8s runner 未挂 sock 或需要强隔离时使用 |

**镜像仓库**：`.docker-build` 使用 `BUILD_DOCKER_REGISTRY`（默认 `registry.example.com`）。`.harbor-push` 优先 `UPLOAD_HARBOR_REGISTRY`，留空时回退 `BUILD_DOCKER_REGISTRY`。

**AUTO_PUSH（推荐用法）**：k8s runner 多节点场景下，独立的 `.harbor-push` job 可能落在不同 node，看不到本地镜像。设置 `BUILD_DOCKER_AUTO_PUSH=true` 后，`.docker-build` 会在同一 pod 内完成 login + push,避免跨 pod daemon 隔离问题：

```yaml
variables:
  BUILD_DOCKER_REGISTRY: "registry.example.com"
  BUILD_DOCKER_IMAGE_NAME: "myapp/service-a"
  BUILD_DOCKER_AUTO_PUSH: "true"
```

**镜像仓库凭据**：在 GitLab CI/CD Variables 中 masked 注入 `HARBOR_USERNAME` 与 `HARBOR_PASSWORD`。`.docker-build` 和 `.harbor-push` 共用这一组凭据。

**Tag 策略**（`.docker-build` / `.harbor-push` 一致）:
1. `BUILD_DOCKER_IMAGE_TAG` / `UPLOAD_HARBOR_IMAGE_TAG` 显式指定 → 最高优先
2. `$CI_COMMIT_TAG`(tag push 场景，如 `v1.2.3`)
3. `$CI_COMMIT_SHORT_SHA`(普通 push,commit id 前 8 位) → 默认

多镜像场景请用 GitLab 原生 `parallel: matrix` 复用 `.docker-build`（见 `examples/multi-image-docker.gitlab-ci.yml`）。


## 构建加速与缓存

缓存依赖 runner 端的 minio 分布式缓存（k8s runner）或本地磁盘（shell runner）。各能力缓存/提速开关：

| 能力 | 缓存/提速 | 默认 | 业务侧动作 |
|---|---|---|---|
| `build/go` | `GOMODCACHE`+`GOCACHE` 缓存到 `.gocache/`（key `<项目ID>-go`） | 自动 | 无需配置 |
| `build/nodejs` | `node_modules/`+`.npm/` 缓存 | 自动 | 无需配置 |
| `build/java` | `.m2/repository` 缓存 | 自动 | 无需配置 |
| `build/cpp` | ccache（cmake `COMPILER_LAUNCHER` / make `CC`/`CXX`），缓存 `.ccache/` | 关闭 | 编译机装 `ccache`，设 `BUILD_CPP_CCACHE_ENABLE: "true"` |
| `lint/js` | 预装镜像免 `npm install` | **默认启用**（`LINT_JS_IMAGE` 已指向预装镜像）| 无需配置；换原生 node 镜像则回退 npm install |
| `lint/js` | 仅 JS/TS 变更才触发的 rules 片段 | 不启用 | job `rules` 用 `!reference [.lint-js-mr-changed, rules]` 或 `.lint-js-push-changed` |

**pipeline 取消策略**：`.base-job` 默认 `interruptible: false`，不主动取消任何 pipeline。多人合并同一分支时 GitLab 仅按目标分支分组取消、无法区分来源分支，故不启用自动取消以免误取消他人 pipeline。

**约定**：
- 覆盖 `*_IMAGE` 时填写自己的镜像仓库地址。
- `build/docker` 只支持 `docker build`（走宿主 `/var/run/docker.sock` 或 dind service 的 daemon），不启用 BuildKit；多镜像构建用 GitLab 原生 `parallel: matrix` 复用同一 `.docker-build` 能力（见 `examples/multi-image-docker.gitlab-ci.yml`）。
- 部分能力（`.checkmarx` / `.cocos-build`）默认走 `CI_BASE_IMAGE`,业务侧根据实际工具供应覆盖镜像。
