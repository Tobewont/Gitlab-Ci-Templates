# 组装示例、Secret 管理与注意事项

> 本文档由仓库根 `README.md` 拆分而来，聚焦「组装示例、Secret 管理与注意事项」。总览与导航见 [README](../README.md)。

## 组装示例

**Python Pylint + AI 评审 + 通知**（业务侧 `.gitlab-ci.yml`）：

```yaml
include:
  - project: 'group/gitlab-ci-templates'
    ref: stable                     # 推荐 stable（稳定线）；详见 docs/发布与兼容契约.md
    file: 'lint/python/jobs.gitlab-ci.yml'
  - project: 'group/gitlab-ci-templates'
    ref: stable
    file: 'review/ai/jobs.gitlab-ci.yml'
  - project: 'group/gitlab-ci-templates'
    ref: stable
    file: 'notify/jobs.gitlab-ci.yml'

stages:
  - lint
  - review
  - notify

# LLM_API_KEY / GITLAB_TOKEN 通过 GitLab CI/CD Variables 注入

my-pylint:
  extends: .pylint

my-ai-review:
  extends: .ai-review

my-notify:
  extends: .notify
  stage: notify
  needs:
    - job: my-pylint
      optional: true
    - job: my-ai-review
      optional: true
```

## Secret 管理

公共模板只声明变量名和占位默认值，**真实 Token / API Key 不出现在 YAML 或 Git 仓库**。

1. **配置入口**：GitLab 项目/群组 → Settings → CI/CD → Variables → Add variable。勾选 **Mask variable**（日志打码）、**Protect variable**（仅受保护分支/Tag 可读）。
2. **变量名对齐**：GitLab CI/CD Variables 里配的变量名与模板一致，配置即生效。

| 用途 | 模板变量 | GitLab Group 级 CI/CD Variables |
|---|---|---|
| LLM API Key | `LLM_API_KEY` | `LLM_API_KEY` |
| GitLab API Token | `GITLAB_TOKEN` | `GITLAB_TOKEN`（建议 Project/Group Access Token，`read_api`） |
| Git 制品仓认证用户名 | `GITLAB_USERNAME` | 全局默认 `oauth2`（配 Personal/Project/Deploy Token）；用 CI Job Token 时改 `gitlab-ci-token`。`UPLOAD_GITLAB_USERNAME` / `DOWNLOAD_GITLAB_USERNAME` 默认引用它 |
| SonarQube Token | `QUALITY_SONAR_TOKEN` | CI/CD Variables，masked |
| 镜像仓库凭据 | `HARBOR_USERNAME` + `HARBOR_PASSWORD` | CI/CD Variables，password 用 masked |

3. **业务侧 YAML 只覆盖非 Secret 配置**，不要在 YAML 里写死 Secret。
4. 定期轮换 Token / API Key；用 Project/Group Access Token 代替 Personal Token。


## 注意事项

- 通知查询 pipeline 状态使用 `NOTIFY_GITLAB_TOKEN`，默认值是 `GITLAB_TOKEN`。飞书、企微、钉钉、通用 webhook 的地址分别注入对应的 `*_WEBHOOK_URL`。
- 使用了变更文件相关能力（`.pylint` / `.ai-review` / `.go-vet` 等）的模块需要 include `common/jobs.gitlab-ci.yml`；查看 `examples/` 了解典型组装。
- 极简镜像（如 `python:3.13-slim`、`node:*-alpine`）里没有 git/curl 时，`.get-changed-files` 会自动用 `apk`/`apt-get` 安装。为提速建议业务侧使用预装 git 的镜像。
