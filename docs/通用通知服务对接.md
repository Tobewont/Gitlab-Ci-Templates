# 通知渠道对接

`notify/` 把流水线文案发到飞书、企业微信、钉钉或任意 HTTP webhook。四个渠道都是机器人 webhook 直连。

## 渠道

| 渠道 | 变量 | 请求 |
| --- | --- | --- |
| 飞书 | `NOTIFY_FEISHU_WEBHOOK_URL`，可选 `NOTIFY_FEISHU_SIGN_SECRET` | `POST` 飞书自定义机器人，`msg_type=text` |
| 企业微信 | `NOTIFY_WEWORK_WEBHOOK_URL`，可选 `NOTIFY_WEWORK_MENTIONED_MOBILES` | `POST` 群机器人，`msgtype=text` |
| 钉钉 | `NOTIFY_DINGTALK_WEBHOOK_URL`，可选 `NOTIFY_DINGTALK_SIGN_SECRET` | `POST` 自定义机器人，`msgtype=text` |
| Webhook | `NOTIFY_WEBHOOK_URL` | `POST` JSON `{"text": "<标题与正文>"}` |

Webhook 地址放在 CI/CD Variables，勾选 Mask。不要写进 `.gitlab-ci.yml`。

飞书机器人在群设置里添加「自定义机器人」。安全设置选「签名校验」时，把密钥填到 `NOTIFY_FEISHU_SIGN_SECRET`。

## 怎么发

聚合入口按 `NOTIFY_CHANNEL` 串行发送，默认 `feishu`。多个渠道用逗号分隔，例如 `feishu,wework`。某个渠道失败不影响其他渠道。地址为空、HTTP 不是 2xx、或响应里的 `code` / `errcode` / `StatusCode` 不是 0，该渠道记失败。默认 job 仍成功。`NOTIFY_PREHEAT_STRICT=true` 时预告 job 失败。

```yaml
my-notify:
  extends: .notify
  variables:
    NOTIFY_CHANNEL: "feishu,wework"
```

也可以单独 `extends: .notify-feishu` / `.notify-wework` / `.notify-dingtalk` / `.notify-webhook`。`.notify-feishu-bot` 与 `.notify-feishu` 相同。

正文由 `NOTIFY_SCENARIO` 选择场景文案（`pipeline` / `build` / `deploy` / `scan` / `review` / `compliance` / `smoke`）。`NOTIFY_TITLE_TEMPLATE` 与 `NOTIFY_MSG_TEMPLATE` 可以整段覆盖。正文里带流水线地址。

预告 `.notify-preheat` 默认在 `.pre` 阶段发送，不查流水线状态。渠道用 `NOTIFY_PREHEAT_CHANNEL`，地址与上表相同。`NOTIFY_PREHEAT_TEXT` 为空时，按重启预告拼正文，`NOTIFY_RESTART_LEAD_MINUTES` 必须是正整数。

## 发不出去时

1. 日志有 `[skip] ... 未配置`：对应 Webhook 地址为空。
2. 飞书签名错误：核对 `NOTIFY_FEISHU_SIGN_SECRET` 与机器人安全设置。
3. 企微、钉钉被拒绝：检查机器人的关键词和 IP 限制。
